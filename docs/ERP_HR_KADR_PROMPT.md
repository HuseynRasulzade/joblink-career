# PROMPT (ERP-yə verilən hissə)

You are a senior ERP engineer building the **HR / personnel records (Kadr) module for Azerbaijan** (Labor Code "Əmək Məcəlləsi", Tax Code, Social Insurance Law). Payroll maths is in parts 1–2; here you build the **processes and records**. First ask me briefly which ERP objects exist (employee master, org units, documents, workflow engine, calendar, notifications), then deliver: data model, services with the rules below, screens, permissions, reminders (cron), imports/exports, automated tests that reproduce section 15, and a short admin guide. Keep legal wording editable by an administrator (it is a draft).

## 0. Principles
1. **The employee card is the single source of truth.** Orders, timesheet, payroll, leave balance and reports **read** the card; they never keep their own copy of salary, position, department, branch, status or dates. Changes to the card happen through an order (or an audited edit) and are always **historized and undoable**.
2. **Application → order → effect.** Absence and many changes start with the employee's written application (ərizə); the order is prefilled from it; when the order is fully signed its effect is applied automatically (card, timesheet, payroll, schedules) and can be reversed from the order page.
3. **Nothing is silently deleted.** Every create/edit/approve/return/reverse writes an audit entry (who, when, what). Views of salary and personal data are logged.
4. **Least privilege.** Rights are granular (section 1); sensitive personal data is separate from general HR rights and can be encrypted at rest.
5. **Dates:** ISO `YYYY-MM-DD` internally, `DD.MM.YYYY` in documents; time zone Baku (UTC+4, no DST); the production calendar (part 2, B) drives working days.
6. All rules that depend on law (limits, percentages, deadlines) are **settings with defaults**, each with the article reference shown in the UI.

## 1. Roles and permissions
**Roles (per company):** `owner` (all rights, manages team), `director` (final approver; sees salaries and invoices), `hr` (HR manager: approves requests, sends offers, manages employees and pay), `manager` (department head: creates vacancies (needs HR+director approval), views candidates, leads own team), `recruiter` (works with candidates), `auditor` (**read-only**: pay, staff, attendance, documents, reports; **cannot change anything and cannot see personal data** such as IBAN, FİN).
**Permissions (18):** `team`, `publish`, `approve-hr`, `approve-director`, `salaries`, `billing`, `company-profile`, `offers`, `reports`, `tests`, `employees`, `staff`, `orders`, `attendance`, `documents`, `personal-data`, `audit`, `payroll`. Groups: Recruitment (publish, approve-hr, approve-director, offers, tests), Staff (employees, staff, orders, attendance, documents, personal-data), Finance (salaries, payroll, reports, billing), Company (company-profile, audit, team).
- `owner`, `director`, `hr` get the **daily HR work set** automatically: `employees, staff, orders, attendance, documents, personal-data, payroll`. Lower roles get each permission only as an explicit grant. `team`, `approve-director` are not grantable; `billing`, `team`, `personal-data`, `salaries` are flagged **sensitive** in the UI.
- **Presets** (a role + grants): HR officer (`employees, orders, documents, personal-data, attendance`), Timekeeper (manager + `attendance`), Org planner (manager + `staff, reports`), Order/document clerk (recruiter + `orders, documents`), Finance/payroll specialist (manager + `salaries, reports, attendance`), Vacancy lead (manager + `publish, offers, tests`), Analyst (manager + `reports`).
- Every API path maps to one permission (default for unknown paths = `salaries`, i.e. restrictive). A permission check = role default OR explicit grant.
- Separate audit journal (`audit`): who did what; salary/personal-data views logged.

## 2. Employee master (card)
**Core fields:** id, linked user account (optional; employee can self-serve), name, FIN, position, department, section, branches (many), `status` (`active`, `leave`, `left`, `removed`), start date, end date, contract end date (empty = open-ended), probation end date, salary (qəpik) + `salary_type` (gross|net) + sector (private|public) + weekly hours, `work_mode` (standard or a named schedule), `exit_type` / `exit_reason`, photo (resized client-side, content-checked), `manager_id` (direct manager; leave applications go to them first) and `deputy_id` (acts while the manager is away), `shift_work` (+ default shift, work/rest days rhythm, rhythm offset), `night_percent` (from the contract), `insurance_before` (months of insurance record before this job; benefits need 6), `main_job` (work book kept here; tax reductions apply only here).
**Personal profile (separate access, section 1 `personal-data`):** birth date/place, gender, citizenship, FIN, ID series/number/issued by/issued date/**expiry**, address and registered address, marital status, children under 14, sole parent, **disability** (`under61`, `p61_80`, `p81_100`), degree (I–III), caused-by-war flag, disability document and **valid-until date**, number of disabled children, `care_dependent` (child | adult81 | degree1), **tax benefit** (one chosen id), its document and from-month, `dependents3`, SSN, VÖEN, IBAN, bank name/code/account/card/holder, pay method (bank|card|cash), education level, military status, emergency contact.
- **Field encryption:** FİN, SSN, VÖEN, ID number, IBAN, account number and card number are sealed with **AES-GCM** (key = SHA-256 of a server secret, ≥16 chars) into one `__enc` string inside the profile; read back only through a "reveal" call. If sealed data exists but the key is wrong/missing the profile is `locked` and **nothing may be saved over it**. Without a key the profile is stored plainly.
- **Visibility:** the profile is shown only to users with `personal-data`, the director and the account owner (the employee). Auditors never see it.
- **History (card timeline):** every change from an order or an edit: salary, position, department, branch moves (links with from/to dates and role), status, contract changes, discipline, substitution, schedule changes, name change, promotions. Each entry has before/after so it can be **undone**.
- **Duplicates:** an employee is matched by FIN; duplicate FIN is refused/merged with a warning.
- **Employee-user link:** an employee can be invited; the linked account sees only their own card, payslips, leave balance, applications ("İş yerim").

## 3. Organization
Branch → Department → Section → Position hierarchy; staff table with places, rate, pay band, level, start/end month (part 2, K); org chart (with optional employee photos, lazy-loaded); branch filter. **Holding/group:** a group of companies can be created; a company joins only by **consent**; the group sees only a **consolidated summary** (no personal data).

## 4. Document folder and retention
- **Categories and types** (each document names its type; "Digər" lets the user write it): **Contract** (employment contract, addendum, probation agreement, full-liability agreement, NDA, civil-law/podrat contract, training/study contract, non-compete), **Order** (hire, leave, salary change, transfer, termination, trip, bonus, discipline), **ID** (ID card, passport, military registration, SSN certificate, family composition, 3×4 photo, registered-address certificate…), **Education/certificate** (bachelor/master diploma, school certificate, professional certificate, course certificate, language certificate, academic transcript), **Medical** (086 certificate, initial/annual examination, insurance policy, disability certificate, vaccination), **Other**.
- Label: `"<type> · № <number> · <date>"`. A document must state its type (listed or free text ≤80 chars).
- **Expiring dates registry:** ID expiry, disability decision validity, and any document `expires`: all within **30 days** (including already expired) are listed and a daily job reminds the company a month ahead; each reminder is sent once.
- **Generated documents** (editable drafts with blanks for unknown values): employment contract, addendum, work certificate, full-liability agreement, confidentiality undertaking.
- **Retention periods** (years; company may change each): personal files and employment contracts **75**; HR orders (hire/transfer/termination) **75**; leave and permission orders **5**; timesheet/attendance **5**; payroll documents **75**; OHS journals and accident acts **45**; documents of rejected candidates **1**. `retentionEnd(endDate, years)` = the date the papers of a leaver may be considered for destruction (same day, years later).
- **Acknowledgement with text hash:** when an employee confirms a rule/instruction/policy, store SHA-256 of the exact text shown so the version they accepted can be proven; rules are versioned.

## 5. Orders (əmr)
**35 kinds in 5 groups** (id → label → form fields → timesheet code):
- *Hire and termination:* `hire`, `probation` (result), `extend` (contract extension, to), `reduction` (staff reduction), `termination`.
- *Leave:* `vacation` (annual; `annual`), `maternity` (`maternity`), `childcare` (`childcare`), `paternity` (`paternity`), `study` (`study`), `unpaid` (reason from the art. 130 list; `unpaid`), `recall` (recall from leave), `addleave` (`addleave`), `creative` (`creative`), `postpone`, `extendleave`, `compensation` (days, termination only).
- *Permissions and special cases:* `donor`, `medical`, `summons`, `military`, `downtime`.
- *Work place and mode:* `remote`, `restday`, `overtime`, `trip`, `training`, `transfer` (position/department/section/branch, optionally with salary), `substitute`, `schedule`, `suspension`, `name`.
- *Pay and reward:* `salary`, `bonus`, `discipline`.
- **Numbering:** `YYYY-<PREFIX>-<4 chars of employee id, upper>`; prefixes: hire İQ, vacation M, maternity AN, childcare UQ, paternity AT, study TM, unpaid ÖM, recall GÇ, trip EZ, training TL, salary ƏH, bonus MK, transfer K, substitute ƏV, schedule İR, probation SM, extend UZ, suspension KN, name AD, discipline İT, reduction Üİ, termination X, addleave ƏM, creative YM, postpone MK, extendleave MU, compensation KP, donor DN, medical TM, summons ÇG, military HT, downtime BD, remote Uİ, restday İG, overtime Aİ. The register flags **duplicate numbers within a year** (case-insensitive).
- **Unpaid leave reasons (ƏM 130) with longest length (calendar days):** family/social matters (130-i) 7; woman with child under 16 / sole parent / guardian (130-c) 14; man whose wife is on maternity leave (130-b) 14; care of a chronically ill child under 4 (130-a) no limit; employee with a disabled child or raising a child with HIV (130-x, 130-ə) 14; care of a sick family member with a medical opinion (130-h) 14; employee with disability under 18 (130-ç) 30; veteran/wounded in defence of territory (130-d, 130-e) 14; doctoral/adjunct study (130-f) 30; entrance exam to higher (14) / secondary special (7) school (130-g) 14; invention/rationalization (130-ğ) 14; other (by agreement) no limit. Exceeding the limit = a warning, not a block.
- **Document text:** each order builds a standard text (title, paragraphs, signature) from the form; missing values stay as `[daxil edilməlidir]`; money as `1 234,50 AZN`; the offer letter to a current employee (new post, raise, transfer) is built the same way.
- **Approval flow (imza axını):** signers are (1) the **section/department head** and (2) the **company director**, picked automatically from the staff list: head = a person in the same section (else department) with title level ≥5 who is not the company director, else a level-4 manager of the same section/department; director = a person whose position is exactly Direktor/Baş direktor/İcraçı direktor/General director/CEO/Managing director/President (deputies/vice excluded), else the director's name from the company profile. Names compared accent- and case-insensitively. States: `pending` → `returned` → `signed`. The **holder** is whose turn it is (`head`, `director`, or `creator` = HR who drew it up). Operations: `approve` (only the holder; the last approval = `signed`), `return` with a reason of ≥3 characters (goes to the previous holder; that person and everyone after them must approve again; the director returns to the head, the head to the creator), `edit` by the creator (clears all approvals, goes to the first signer), signed orders **cannot be edited or returned**. History events: created, approved, returned, edited, signed (by, at, role, to, note). An order with no signers is signed at once.
- **Registry (reyestr):** columns number, date, kind, employee, status, holder, waiting days; quick filters: pending, returned, signed, **stale** (not signed and not moved for ≥3 days), **unapplied** (signed, effect supported, not yet applied), **duplicate numbers**. `waitingDays` = days since the last movement (created/approved/returned/edited); signed orders do not wait. Reminders for stale orders.
- **Effects on signing** (a "plan" is computed and previewed in the form before sending; applied when fully signed; the previous values are stored for undo):
  - `transfer`: new position/department/section (patch the card), salary if given; a **branch move** ends old branch links the day before and starts the new link on the effective date (pay and bonus follow from that day).
  - `salary`: new salary on the effective date; `name`: new name; `bonus`: an amount added to the **order-date month's** pay as a bonus line; `discipline`: an entry in the card history with the penalty text.
  - `termination` / `reduction`: status `left`, end date = effective date; reduction sets exit type `dismissal`, reason `restructuring`; **offboarding checklist opens automatically**.
  - `probation`: a successful result clears `probation_end`; a failed result (words like keçmədi/uğursuz/neqativ/qane etmir/yararsız/failed) changes nothing.
  - `suspension`: marks the days in the timesheet; `extend`: sets the contract end date and writes a contract event; `substitute` and `schedule`: history events (schedule also sets `work_mode`).
  - Leave/absence kinds with a timesheet code mark the days automatically; vacation/addleave/creative also set the leave-schedule entry to "taken" and update the balance; `overtime`/`restday` orders **approve** the extra hours for pay; `hire`: the card and start date equal the order.
  - A change dated in the future is shown as "from DD.MM.YYYY".

## 6. Applications (ərizə) and employee self-service
- **Application kinds:** annual, additional, creative, study, unpaid, childcare, maternity, paternity leave; postpone; extend leave; compensation (only on termination, 144.1); donor day; medical examination permission; remote work; schedule change/part-time (ƏM 94); name change; **resignation** (termination); plus a free-text **"other"** application that needs an HR answer and creates no order.
- **Statuses:** `new`, `ordered` (an order was drawn up from it), `rejected`, `answered`, `withdrawn`.
- **Validation (blocks saving):** start date required where the kind has one; end date required (except remote); end ≥ start; compensation needs days > 0; unpaid/extend/postpone/schedule/name need a reason ≥2 chars; "other" needs text ≥5 chars.
- **Warnings (do not block):** vacation order must be issued **≥5 days before start** (ƏM 138.2); resignation needs **one calendar month's notice** (69.1; the earliest date shown; 31 Jan + 1 month = last day of Feb); unpaid leave over the reason's maximum; compensation only on termination.
- **Order prefill:** kind, dates, quantity, vacation kind, and basis text `"işçinin DD.MM.YYYY tarixli ərizəsi: <reason> (<basis>)"`. The order always rests on an application.
- **Approval chain for leave:** employee → **direct manager** (deputy if away) → HR gate → order; overlapping leaves/blackouts are refused; a leave without a matching order raises a warning.
- **Employee can:** see own card summary, payslips (approved months only), leave balance and schedule, write applications and messages to the company, request a **data change** (HR approves), confirm asset handover and rule acknowledgements, give feedback/surveys, upload own photo.

## 7. Leave management
Entitlement, dates, pay, balance accrual: part 2, D. Here: the **yearly leave schedule** (entries: employee, start, end, days, status `proposed|approved|rejected|taken`), holidays inside a leave are not counted and push the end date (114.6), **department overlap check** (the busiest day's number of people away vs a threshold; warnings on dates that overlap), monthly load chart, Excel import (matched by FIN) with preview, link to the application and the order. `leaveDays(from,to)` = calendar days inclusive (0 if to<from).

## 8. Attendance and shifts
- **Timesheet:** part 2, B (statuses). Filled by HR, by orders, by employees' own clock-ins, by shift plans and by imports; an approved payroll month is locked.
- **Clock-in rules (company settings):** day start/end (default **09:00–18:00**), break (**60 min**, deducted only when the span exceeds 4 h), grace (**10 min**). `hoursFromClock(in,out,break)`: if out<in the shift passes midnight; **night time = minutes inside 22:00–06:00**; `late` = minutes after start **only if > grace** (else 0); `early leave` = minutes before end only if > grace; an overnight shift is not judged by day rules.
- **Geofence (optional):** modes `off`, `warn`, `require`. Only the **distance** to the office is calculated and stored (haversine, metres); coordinates of the person are **not stored**. `require` refuses a clock-in outside the radius or without a position; `warn` allows it and leaves a note for HR.
- **Employee self-entry** with HR confirmation; **overtime approval**: when the company requires it, overtime/rest-day hours count only on approved days or by an order (part 2, C).
- **Shifts:** named shift types (start/end, may pass midnight), per-employee rhythm (`work` days on, `rest` days off, offset), pattern fill over a date range, swap requests. **Planner warnings** (limits are settings): `away` (shift on a day the employee is on leave/trip/sick), `rest` (too short a rest between shifts), `streak` (too many days in a row), `cover` (a department below its **minimum** number of people on a shift on a day when any shift is planned; days with no shift are not judged). Only employees flagged `shift_work` are planned.

## 9. Probation and contracts
Probation limits: part 2, H. The card holds `probation_end`; reminders before it ends; the `probation` order clears it on success. `contract_end` empty = open-ended; reminders before a fixed-term contract ends; `extend` order moves it. Work-mode changes (`schedule`) and part-time are recorded in history.

## 10. Offboarding
Checklist (each item done/at/by; progress = done/10): signed termination order; company property returned (assets module); access closed; work handed over; **unused leave computed** (compensation, part 2 H); **final settlement paid** (ƏM 77, 172); work book and registration; employment certificate if asked; **exit interview held**; personal file sent to archive. **Exit interview questions:** main reason (better offer, pay, no growth, relationship with manager, conditions, other…), 1–5 scores for manager / conditions / pay / growth, would recommend (yes/no), would return (yes/no), what to change (text). Answers are aggregated for turnover analysis. The checklist opens automatically from a termination/reduction order.

## 11. Occupational safety (əməyin mühafizəsi) and legal compliance
- **Records:** *Briefings* — kinds intro, initial, repeat, extra; needs instructor name; employee e-signature flag; `due` default: **6 months** for initial/repeat, none for intro/extra. *Medical examinations* — kinds initial, periodic, extra; result `fit | limited | unfit`; clinic; `due` default **12 months** (none for extra). *Incidents* — kinds near-miss, minor, serious, fatal, illness…; place, description (≥5 chars), cause, measures, days lost (0–3650), status `open | investigating | closed`.
- `dueState(due, today, soon=30)`: `overdue` (< today), `soon` (≤30 days), `ok`, `none`. Due dates are added with end-of-month clamping (31 Aug + 6 months = 28 Feb).
- Versioned company rules/instructions with **employee acknowledgement** (text hash) and consent; reminders for overdue briefings and examinations.

## 12. Employee rights engine (disability, children, tax benefits)
From the personal profile compute, for HR and the calculators (each with its article):
- **Weekly hours:** under 16 → **24 h**; 16–17 → **36 h**; disability 61–100 % → **36 h**; otherwise **40 h** (ƏM 91.2/89.3); pay stays that of the full norm (159.2). Age on a date: `year diff − (before birthday ? 1 : 0)`.
- **Rights list** (examples with articles): short week (91.2, 159.2); leave at a convenient time (133.3) and leave of the first year after six months (131.4) and part-time on medical opinion (94.3) for disabled employees; under-18 disabled: leave ≥42 days (119.2, 116.3) and one month unpaid (130-ç); disabled child: 14 days unpaid (130-x/ə), retention priority in reductions (78), and for mothers +5 leave days (117), no night work/overtime/rest-day work/trips without written consent, convenient leave; carers of persons needing permanent care: retention priority (78).
- **Income-tax benefits (monthly reduction of taxable wage; VM 102):** 800 AZN — martyr's parents/widow/children (102.1-1). **400 AZN** — Hero of the Patriotic War (102.2.1), National Hero (102.2.1-1), Soviet Hero (102.2.2), full holder of the Order of Glory (102.2.3), war-disabled groups I–II (102.2.4), widow/children of fallen fighters (102.2.5), rear-front awardees (102.2.6), war veterans (102.2.7), Chernobyl/radiation (102.2.8), mine-clearance victims' family (102.2.9). **200 AZN** — disability 61–100 % (102.3), disabled child, permanent carer of a disabled child / 81–100 % disabled (102.3). **100 AZN** — parents of fallen servicemen/officials (102.4.1), January-20 and territorial-integrity families (102.4.2), Afghanistan/combat-country servicemen (102.4.3), carer of a degree-I disabled (102.4.4), internally displaced (102.4.5). **+50 AZN** — supports ≥3 people (102.5).
- **Rules:** only the **largest single benefit** of 102.1-1…102.4 is given (102.7); the +50 for ≥3 dependents is added to it; applies **only at the main workplace** (`main_job`) and **from the month the papers were handed in** (102.8). `taxReduction = (mainJob ? (startedByDate ? benefitAmount : 0) + (dependents3 ? 50 : 0) : 0)`. The value feeds the payroll engine's `reduction` (part 1). Suggested benefit from the profile: war-disabled I–II → 400; disability 61–100 % (not war) → 200; carer of child/adult81 → 200; carer degree-I → 100; the employee still hands in documents.
